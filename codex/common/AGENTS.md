## Codex 하네스

- 한국어로 응답한다. 프로젝트 코드와 실제 빌드 설정을 먼저 확인하고 기존 컨벤션을 따른다.
- 하네스 설정은 `.codex/harness/manifest.json`, 상세 기준은 `.codex/harness/references/`에 있다. 이 경로는 프로젝트 루트 기준이다.
- 작업 유형에 맞는 `$harness-*` Skill을 사용한다. 앱은 feature/design/logic/connect-api, 라이브러리는 component/publish 절차를 사용한다.
- 구현은 탐색 → 수정 → 검증 → 보고로 진행한다. 요청된 가역적 작업은 계속 진행하고, 필수 명세가 없으면 해당 부분을 추측해 구현하지 않는다.
- 구현 후 `node .codex/harness/verify.cjs`를 실행한다. 종료 코드 0=설정된 검사 통과, 1=검사 실패, 2=검증 불가. 2를 PASS로 보고하지 않는다. 검사별 결과와 생략된 항목을 최종 보고에 구분한다.
- DoD가 있는 작업은 항목별 근거를 남긴다. 독립 checker를 사용할 수 있고 위임이 허용된 경우 `.codex/harness/references/checker.md`를 전달해 판정받는다. 사용할 수 없으면 자가 검증임을 밝히고 독립 검증 PASS를 주장하지 않는다.
- 검증 실패는 수정 후 다시 확인하되 같은 문제의 수정·재판정은 최대 3회다. 환경 문제는 코드 오류와 구분하고 필요한 조치를 보고한다.
- 런타임 확인은 `.codex/harness/references/smoke.md` 기준이다. 기기/브라우저 없이 컴파일만 통과한 것을 실행·렌더링 성공으로 보고하지 않는다.
- 여러 작업이 같은 빌드 산출물을 변경하면 별도 worktree를 사용한다. 다른 세션의 빌드를 중단하거나 캐시·산출물을 지우지 않는다.
- 커밋·푸시·배포·외부 코멘트 게시는 사용자가 요청한 범위에서만 수행한다. 리뷰 요청만으로 GitHub에 게시하지 않는다. 키·토큰을 코드·로그에 남기지 않는다.
- 반복 유지보수는 포맷 등 기계적 수정만 한다. 동작 변경·공개 API 변경은 현재 작업 범위인지 확인한다. 반복 일정은 사용자가 요청할 때만 만든다.
- 재발한 프로젝트 규칙은 이 파일의 사용자 관리 영역에 기록한다. 자동 차단은 검증 스크립트/CI로 구현하며 실제 등록 없이 자동 실행된다고 설명하지 않는다.
