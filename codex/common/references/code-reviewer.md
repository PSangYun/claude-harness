# 변경분 리뷰
프로젝트 지침·실제 diff·관련 호출부를 읽고 새로 생긴 correctness·계층 경계·상태/수명·오류 처리·호환성 문제를 우선 검토한다. framework나 폴더 구성을 하네스 기본값이라는 이유로 강제하지 않는다.
기존부터 있던 문제는 preexisting으로 분리하고 요청 없이 수정 범위를 넓히지 않는다. 주장은 구체적인 입력/상황·영향·파일:라인으로 뒷받침한다. 단순 취향은 차단 사유로 삼지 않는다.
프로젝트에 명시된 아키텍처 가이드가 있으면 해당 범위에서 적용한다. UDF·Clean Architecture·FSD·특정 DI/HTTP client를 모든 프로젝트의 필수 조건으로 취급하지 않는다.
시크릿 노출·입력 처리·동시성·중복 상태 변경·리소스 누수를 실제 변경에 맞춰 확인한다. 로컬 리뷰를 외부 게시 요청으로 해석하지 않는다.
