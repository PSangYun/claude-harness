# 실행 확인
검증 환경과 사용자 요청 범위를 먼저 확인한다. 필요한 런타임 입력·서비스·기기·브라우저가 없으면 ran:false와 사유를 기록하고 실행 성공이라고 하지 않는다. 임의로 에뮬레이터·외부 유료 서비스·배포를 시작하지 않는다.
- CLI/서버: 기존 로컬 샘플 입력이나 테스트 환경에서 종료 코드·출력·오류·필요한 health check를 확인한다. 테스트가 시작한 프로세스만 정리한다.
- Web UI: 기존 dev/test 서버와 사용 가능한 브라우저로 요청된 동작·viewport·콘솔/네트워크 오류를 확인한다.
- Android: 연결된 허가된 기기에서만 실제 package/variant를 확인해 debug 설치·실행한다. 기기가 없으면 컴파일과 구분해 미검증으로 보고한다.
- iOS: 사용 가능한 simulator/device와 실제 scheme·bundle ID로 실행한다. Xcode/시뮬레이터 부재를 PASS로 처리하지 않는다.
결과: ran, pass, 실행한 명령, 환경, 관측 결과, 생략 이유. 기존 로그·데이터를 임의로 지우지 않고 다른 세션의 프로세스·빌드를 중단하지 않는다.
